# Как устроена подготовка к интервью в этом репо

## Структура

| Папка | Что внутри |
| `keys/` | **Мои answer keys.** Компактные эталонные ответы (обязательные пункты + типичные ошибки + красные флаги). Для больших разделов разбиты на `.part2`/`.part3`. Используются для проверки — не подглядывай до ответа. |
| `qa/` | **Твоя рабочая зона.** 16 файлов по разделам, под каждым вопросом — `## Your answer`. Пиши ответ туда (bullet-формы достаточно). |
| `reference/` | Исходники ответов из README: статьи outcomeschool.com, Substack-посты, транскрипты YouTube, посты LinkedIn/X — скачаны через Exa. `_manifest.json` = url→файл, `_qmap.json` = вопрос→источники. |
| `resume/` | **Твоё резюме** (`resume.md`, verbatim из PDF) — **локально, в git не коммитится**. Раздел `16-resume-deep-dive` — предметное интервью: вопросы по твоему опыту, проверка не теории, а того, что ты можешь защитить каждый буллет. |
| `QUESTIONS.md` | Оригинальный список вопросов (upstream, не трогать) — со ссылками на полные ответы-источники. |

## Цикл подготовки

1. Открой файл раздела в `qa/`, ответь на вопросы под `## Your answer` — своими словами, коротко.
2. Скажи мне: **«проверь <файл>»** (или просто открой сессию — я вижу `qa/`).
3. Я сверю каждый ответ с `keys/<тот-же-файл>.md`:
   - **✓** — покрыты обязательные пункты;
   - **±** — частично: скажу, чего не хватает;
   - **✗** — неверно/пусто: дам правильную суть и ссылку на `reference/<slug>.md`.
4. При желании — могу спрашивать устно: «задавай мне по 5 вопросов из раздела X».

## Порядок разделов (от ядра к периферии)

`01-must-know` → `02-llm-fundamentals` → `04-rag` → `05-agents` → `03-prompt-engineering` → `07-vector-db` → `09-llmops` → `10-evaluation` → `13-infrastructure` → `06-fine-tuning` → `08-system-design` → `12-multimodal` → `11-safety` → `14-coding` → `15-behavioral` → `16-resume-deep-dive`

571 вопрос теории + 30 предметных по резюме. Реалистичный темп — 20–30 вопросов в день. Раздел 16 можно прогонять в любой момент — он про твой опыт, не про теорию.
